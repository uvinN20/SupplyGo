# Business profiles

SupplyGo suppliers and sellers can save business details separately from their login credentials. Use Java 25 and the TLS setup in [AUTHENTICATION.md](AUTHENTICATION.md). No additional server flags are required.

## Desktop workflow

1. Connect to the TLS server and sign in as a supplier or seller.
2. Open **Business profiles** and choose **Load my profile**. A new account displays “No business profile yet”.
3. Enter full name, business name, contact number and town/location, then choose **Save profile**.
4. Use **Load my profile** to reload the saved record. Saving again replaces the details while preserving the original creation timestamp.

Managers open the same tab, select their directory and choose **Refresh directory**. **Next page** advances through pages of at most ten profiles; Refresh returns to page one. Only accounts that have saved a business profile appear. All network operations run in Swing background workers. Profile fields and directory rows clear when the account changes, signs out or disconnects.

| Role | Own profile | Supplier directory | Seller directory |
| --- | --- | --- | --- |
| SUPPLIER | Read and edit | No | No |
| SELLER | Read and edit | No | No |
| SUPPLIER_MANAGER | No | Read | No |
| SELLER_MANAGER | No | No | Read |
| ADMIN | No | Read | Read |
| PRODUCTION_MANAGER | No | No | No |

Managers cannot edit another account's profile. The server takes username and role from the authenticated session, never from the request payload. Login credentials are not returned in directory results.

## Validation

All four editable fields are required. Strings must be trimmed and contain no control characters or unpaired UTF-16 surrogates. The desktop trims surrounding whitespace before sending; the server rejects untrimmed raw requests.

| Field | Maximum length | Additional rule |
| --- | --- | --- |
| fullName | 64 UTF-16 code units | Nonblank printable text |
| businessName | 96 UTF-16 code units | Nonblank printable text |
| contactNumber | 32 UTF-16 code units | 7–32 characters, digits/spaces/parentheses/hyphens, optional leading +; starts and ends with a digit after the optional + |
| location | 64 UTF-16 code units | Nonblank printable text |

Leading phone zeros are preserved. Contact validation checks format, not whether a phone number exists. The sum of the four JSON-encoded field strings is limited to 400 UTF-8 bytes, including quotes and escapes. This supports international text while keeping a full directory page within the 8192-byte frame limit. Shorten details if the combined limit is exceeded.

## Protocol

All operations require TLS and a live authenticated session. Use the existing version-1 newline-delimited JSON envelope.

| Request type | Exact payload | Success message |
| --- | --- | --- |
| GET_BUSINESS_PROFILE | {} | BUSINESS_PROFILE |
| UPDATE_BUSINESS_PROFILE | fullName, businessName, contactNumber, location strings | BUSINESS_PROFILE |
| LIST_SUPPLIERS | offset integer 0–10000 | BUSINESS_PROFILES |
| LIST_SELLERS | offset integer 0–10000 | BUSINESS_PROFILES |

Unknown fields, including username and role in updates, are rejected. Directories are filtered by role before pagination and sorted by username. nextOffset is -1 on the final page. Concurrent additions can move entries between pages; Refresh obtains a fresh first page.

Example update:

```json
{"version":1,"requestId":"profile-1","type":"UPDATE_BUSINESS_PROFILE","payload":{"fullName":"Example Seller","businessName":"Southern Fruits","contactNumber":"0771234567","location":"Matara"}}
```

Example response (identity and timestamps generated by server):

```json
{"version":1,"requestId":"profile-1","status":"OK","data":{"message":"BUSINESS_PROFILE","profile":{"username":"seller","role":"SELLER","fullName":"Example Seller","businessName":"Southern Fruits","contactNumber":"0771234567","location":"Matara","createdAt":"2026-10-23T10:00:00Z","updatedAt":"2026-10-23T10:00:00Z"}}}
```

A directory response has message BUSINESS_PROFILES, profiles (an array of the same records), and nextOffset.

Errors include TLS_REQUIRED, AUTH_REQUIRED, SESSION_EXPIRED, FORBIDDEN, PROFILE_NOT_FOUND, INVALID_PROFILE, INVALID_MESSAGE, PROFILES_UNAVAILABLE and STORAGE_ERROR. Normal application errors keep the connection usable. After a connection error during Save, reconnect and load the profile to check whether the save completed before retrying.

## Persistence and concurrency

The server stores schema version 1 in `data/business-profiles.json`, or the directory selected by `-Dsupplygo.data.dir`. A process lock prevents multiple servers from opening the same profile store. Up to 10000 profiles and 8 MiB of JSON are allowed. Back up this file together with users.json while the server is stopped. Do not commit runtime data.

All update transactions synchronize on the repository. Updates write and force a temporary file, atomically replace the destination, then publish the new immutable memory snapshot. A failed replacement leaves the previous in-memory state intact. Concurrent changes to different accounts are preserved; for the same account, the last successful save wins. This module does not offer optimistic editing conflict detection or a change history.

Existing installations need no migration: a missing profile file starts empty. Invalid saved records or schemas prevent startup instead of silently losing data.

## Verification

Run `mvn clean verify` with Java 25. Tests cover role permissions, ownership, validation, protocol response limits, persistence after reopen, concurrent saves, failed atomic replacement and real TLS client/server operations. For a manual check, save a profile, restart the server, reload it, inspect the appropriate manager directory, and verify that logout clears the displayed data.
